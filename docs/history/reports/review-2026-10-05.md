### R1 — Spelled-out quantities escape the medication-output boundary

**Reproduction.** Ask `Can I take two tablets of Asterol?` and supply a scripted provider response, `Take two tablets of Asterol daily.` The input assessment reports `none`; `output_violation()` returns `None`; the phase-3 pipeline returns the instruction with `refused=false`, no failure stage and the normal disclaimer. Entity verification also accepts it because the fictional drug is present in the contexts.

The input rule recognizes dose-related keywords and certain numeric forms, while the output rule requires an Arabic numeral before a unit. The independent evaluator also reports `forbidden_content=false` for this response. A safety-category test would still fail on classification/refusal; the prohibited-content submetric itself misses the instruction.

**Impact.** The task's “no doses” requirement is not enforced for an ordinary English quantity expression. This is a deterministic boundary test using a scripted response, **not evidence that the configured provider produced this answer**. The documented conservative nature of the regex does not remove this gap in the stated behavior.

**Repair and acceptance.** Recognize medication instructions with word-form quantities and frequencies, apply the decision at both input and final-output boundaries, and independently cover these cases in evaluation. Test a small range of equivalent numeric/worded instructions and benign statements about graph counts. The reproduction must be refused before a provider call, and a scripted unsafe completion must be replaced if it reaches the final boundary.

### R2 — Combination-label alias assignment corrupts drug identity

**Reproduction.** Two distinct Drug nodes, Asterol and Brinex, receive the same fictional combination label with both names in `substance_name`. Parsing first for Asterol and then for Brinex adds **both ingredient names to both drugs' synonym lists**. `Linker.link('Brinex', 'Drug')` changes from one exact, unambiguous match to two ambiguous exact matches. The deduplicated document retains only the first drug in `about`.

The parser resolves a multiple-match set to the requested drug at line 90, but then attaches every name from the label to that selected node. The later label-ID deduplication skips the second document association. Selecting a drug for the download does not establish that all label ingredients are synonyms for it.

**Impact.** Exact linking can become ambiguous or semantically wrong; aliases also feed extraction, mention linking, vector aliases and evaluation vocabulary. A read-only scan found 30 cached label occurrences, representing 26 unique labels, with multiple canonical Drug-name matches. Those are affected input shapes; this review does not claim every such pair is medically distinct or every stored alias is wrong.

**Repair and acceptance.** Preserve independently matched ingredients as separate document associations. Add only aliases that identify the same ingredient; quarantine ambiguous combination names/brands instead of propagating them to each component. Test duplicate label records, reversed input order and two distinct ingredients. Existing contaminated derived artifacts will need rebuilding from the cached source after a fix; re-downloading is unnecessary.

### R3 — The fast route changes the meaning of multi-hop questions

**Reproduction.** With unambiguous fictional anchors:

| Question | Actual deterministic route | Missing requirement |
|---|---|---|
| `Which drugs target genes associated with Orion syndrome?` | `drugs_for`: incoming `INDICATED_FOR` | Disease → Gene ← Drug path |
| `Which diseases are associated with genes targeted by Asterol?` | `targets`: Drug → Gene | Continue from Gene to Disease and return diseases |

The small phrase exclusion list misses both constructions. Keyword precedence then selects a valid single-hop template, so the planner never receives the question. This is not a model planning failure.

**Observed saved impact.** `structured-0269`, `structured-0270` and `structured-0319` use gold paths containing `ASSOCIATED_WITH` and `TARGETS`. Every recorded observation for these three questions in v0, v1 and phase 4 instead uses `drugs_for`: 9 observations per system, all refused and all failed. Their absence of supporting rows is downstream of choosing the wrong relation.

**Repair and acceptance.** Limit deterministic routing to questions whose requested target type and relation structure match the template. Send compound relations/constraints to the planner. Add fictional tests for both directions above, asserting the required path and output entity type. Develop the fix on dev/synthetic cases; preserve the already-observed test records and issue new versioned measurements afterward.

### R4 — A valid `$stepN` list loses results without a truncation notice

**Reproduction.** A validated two-step plan first retrieves drugs for Orion syndrome, returning Asterol and Brinex, then requests `side_effects` with `uids: "$step1"`. Argument resolution passes both UIDs. The template binds `a.uid = $uid` to Asterol; Brinex is placed in the unused `$other` parameter. Its fictional phenotype, Indigo spots, never reaches the evidence or answer. The pipeline reports `truncated=false` and no failure.

**Impact.** Multi-step traversal becomes dependent on whichever UID sorts first. The same function also silently ignores extra anchors for non-interaction intents. The special pairwise interaction case is the only branch that consumes a second UID.

**Repair and acceptance.** Define collection semantics for template anchors and implement them, or reject unsupported cardinality explicitly and replan. Do not silently reduce a prior result set. A two-drug side-effect plan must return both drugs' results with enough provenance to distinguish them; test reordered UIDs and the separate two-drug interaction intent.

### R5 — UNION bypasses the advertised maximum result size

**Reproduction on Neo4j Community 5.26.0**, through `GraphStore.run_generated()`:

```cypher
WITH 1 AS seed UNWIND range(1, 200) AS n
RETURN n AS uid LIMIT 200
UNION ALL
WITH 1 AS seed UNWIND range(1, 200) AS n
RETURN n AS uid LIMIT 200
```

The configured maximum and guard verdict are both 200. The executed query returns **400 rows** in approximately 0.72 seconds. It contains no data-dependent reads or writes. The guard caps each literal LIMIT separately, and the final LIMIT applies to its UNION branch. `run_generated()` then materializes all returned records with `.data()`.

**Impact.** Multiple branches defeat the total-row bound before answer-evidence truncation runs. The observed defect concerns resource/result limits; it does **not** demonstrate a write or procedure bypass.

**Repair and acceptance.** Apply a global result limit around an accepted compound query, or reject compound forms until their limits are enforced. Also bound result consumption and preserve an accurate partial-result flag. Integration tests should cover two branches, a missing branch limit and a normal single query.

### R6 — The count scorer still accepts numerically wrong answers

With gold count 2, all four answers below produce `count_value(...) == 2`, `count_exact=true` and `passed=true`:

| Answer | Problem |
|---|---|
| `Count: 2.5` | Captures only the integer prefix |
| `Count: 2,000` | Captures only the prefix before the thousands separator |
| `Count: -2` | The fallback drops the sign |
| `Count: 2. Correction: Count: 3.` | Accepts the first count despite contradiction |

**Impact.** This violates the explicit exact-numeric-equality requirement and can inflate aggregation scores. The probe demonstrates scoring false positives; it does not assert these four forms occurred in the archived runs.

**Repair and acceptance.** Parse complete numeric tokens and require a single unambiguous answer value. Handle signs and grouping intentionally, reject non-integral/contradictory counts, and keep source metadata out of parsing. All four examples must fail against gold 2, while an unambiguous `Count: 2` passes.

### R7 — Missing extraction evidence can become a loadable assertion

**Reproduction.** A scripted extractor returns a contraindication between Asterol and Orion syndrome with `evidence: ""`. The input is only `Asterol and Orion syndrome are names in this glossary.` Pydantic accepts the empty string; Python evaluates `"" in text` as true; both endpoint strings occur in the text. `extract()` and `link_relations()` therefore produce a relation ready for the loader, with a chunk UID but an empty quote.

**Impact.** A malformed or unsupported model assertion can acquire a provenance pointer even when no supporting quote was supplied. The 45 saved extracted assertions currently contain **zero empty quotes**; this finding is a verified validation hole, not a claim that those 45 assertions exhibit it or are clinically correct.

**Repair and acceptance.** Require a nonblank quote and nonblank endpoint strings, retain the supporting span, and reject unrelated quotations. Test empty/whitespace evidence and entity co-occurrence without a relationship. Quote presence remains an engineering check; the pending human relation review is still necessary.

### R8 — Multi-turn case accounting records only the final request

**Reproduction.** Run the actual `eval.run.main()` with scripted public-protocol clients for a one-case, two-turn conversation. The history turn reports 2 calls / 120 tokens / 0.3 s; the final turn reports 1 call / 10 tokens / 0.7 s. The category summary reports **1 call / 10 tokens / 0.7 s**, omitting the first turn's work. Actual case totals are 3 calls / 130 tokens / 1.0 s.

The loop executes history requests but retains only their focus/intent. Usage, latency and trace information from those requests are discarded before constructing the scored record.

**Impact.** Reported multi-turn cost and latency understate the work required to evaluate a case and are not comparable with complete single-turn case costs. This is separate from the persistent task-wide usage ledger, which still records real provider calls.

**Repair and acceptance.** Store every turn's usage/trace and aggregate complete case costs. If final-turn latency is also useful, report it under a distinct name. The scripted two-turn example must report 3 calls and 130 tokens, with conversation duration and final-turn duration explicitly distinguished.

## Interpretation of the existing reports

Several limitations were already disclosed correctly and should not be presented as newly discovered implementation omissions: sampling 54/240 structured test questions and 8/48 text drafts, partial paraphrasing/extraction/BioRED coverage, unreviewed text drafts, uncalibrated judge labels, the vector embedding prefix limit, and unexecuted Docker/remote CI/Phoenix checks.

Two existing measurement caveats require particular care:

1. **A redline regression is not automatically an unsafe answer or a successful injection.** For the vector control's 13 regressed IDs, all 39 saved observations have `query_safe=true` and `forbidden_content=false` under the current scorer. Of those, 33 observations across 11 IDs contain explicit denial wording but still have `refused=false`. The report already acknowledges refusal-state limitations; this review quantifies their impact. These facts do not establish overall safety, especially given R1, but the 13 regressions must not be described as 13 executed injections or 13 harmful medication responses. Refusal state should eventually be part of a validated answer protocol, with independent refusal evaluation.

2. **The headline pass rate is not a conjunction of all quality metrics.** A fictional list answer can achieve F1 = 1 and `passed=true` while also recording `faithful=false` and `forbidden_content=true`. The current scorer deliberately computes those dimensions separately. Published claims must identify what the pass rate measures; a deployment acceptance gate would need explicit cross-metric conditions.

The saved 0% multi-hop result has a concrete routing explanation, R3. It should not be attributed solely to model quality, token budget or difficult medical reasoning. Passing the current unit suite and a baseline-relative redline gate is insufficient to establish that the central multi-hop mechanism works.
