# Follow-up implementation review — 2026-10-05

The existing 99 unit tests and Ruff checks pass, but broader offline probes
confirm **eight remaining issues: two P1 and six P2**. The previous repair fixed
its original reproduction cases; it did not establish complete coverage of the
surrounding input classes. In particular, dose schedules, compound routing,
entity identity validation and ingestion reconciliation need further work.

This review inspects the current uncommitted repair on top of
`b7670bf2b7767c6e091bac9ee0f63e24032ab848`. It changes no application code,
production artifacts, graph data or historical measurements. All examples below
use fictional entities. No real model was called and no data was downloaded.

## Confirmed findings

### F1 — P1: Ordinary dosing schedules escape both output protection and evaluation

**Location:** `src/medkg/qa/safety.py:20–22,60–66`;
`eval/score.py:58–62`.

The schedule expressions recognize “twice a day” but omit numeric equivalents
and common recurring times. A scripted completion, `Take Asterol 2 times a day.`,
passes the complete generation/verification/output path unchanged, with
`safety="none"` and `refused=false`. `Take Asterol every morning.` behaves the
same way. The independent evaluator returns `forbidden_content=false` for both.
The positive control, `Take Asterol twice a day.`, is correctly replaced with a
refusal. Input assessment also misses the two alternate forms.

This is a demonstrated enforcement gap, not evidence that the configured real
provider currently emits these instructions. The evaluation duplicates the same
expression coverage, so agreement between those two checks does not independently
establish safety.

**Correction and acceptance:** recognize numeric frequencies and recurring-time
instructions within the established no-dosing policy. Add independently authored
equivalence tests at input, final output and evaluation boundaries, including
benign graph counts. Every scripted dosing completion must be replaced before
returning it to the caller and must be detected when scored directly.

### F2 — P1: Non-gene multi-hop questions still take a single-hop template

**Location:** `src/medkg/qa/router.py:17–19,28–33`.

`What symptoms are associated with diseases treated by Asterol?` requires
`INDICATED_FOR` followed by `HAS_PHENOTYPE`. The current router selects
`indications`, invokes no planner, and executes only `INDICATED_FOR`. The
end-to-end fictional probe consequently returns `Orion syndrome` instead of
retrieving a phenotype; `failure_stage` is null and `truncated` is false.

The previous correction handles compound questions involving genes/proteins but
does not cover this ordinary Drug → Disease → Phenotype path. Answer generation
cannot recover a second relation that was never retrieved.

**Correction and acceptance:** admit a template only when the requested answer
type and relation structure fit that single-hop intent. Route other compound
questions to the existing planner. Verify both actual path relations and the
returned entity type for Drug → Disease → Phenotype and Disease ← Drug →
Phenotype, alongside the existing gene-path checks and simple-template controls.

### F3 — P2: One exact entity suppresses typo recovery for another entity

**Location:** `src/medkg/qa/linker.py:90–94`.

For `Does Asterol interact with Brinexamne?`, `link("Brinexamne", "Drug")`
individually resolves fictional `Brinexamine` with an unambiguous fuzzy score of
95.238. However, `in_question` returns only Asterol because fuzzy/vector fallback
runs only if the entire question has no exact match. The pipeline therefore
executes a one-drug interaction-neighborhood query: parameter `other` is empty
and the second-drug constraint is absent.

This can miss the requested pair when that drug falls outside the neighborhood
limit, or present unrelated interactions as the evidence for a pairwise question.
The probe establishes the missing constraint, not a specific real-model answer.

**Correction and acceptance:** apply the established linking cascade per detected
mention, preserving mention spans and unresolved anchors. Do not silently treat
an unresolved two-drug question as a one-drug query. Test both mention orders,
exact-plus-typo input, ambiguity and an unrelated neighborhood distractor.

### F4 — P2: A combination label does not invalidate a brand accepted elsewhere

**Location:** `src/medkg/ingest/openfda.py:100–109,124–129`.

A fictional single-ingredient label associates `FamilyBrand` with Asterol; a
second label uses the same brand for Asterol plus Brinexamine. The parser counts
the combination's brand as quarantined, but never adds its ambiguity to the
global brand-candidate decision. The final catalog still resolves FamilyBrand
to Asterol alone, unambiguously. Reversing record order produces the same result.

The current cached dataset check found **zero** single-owner catalog mappings
among its 24 normalized brand names attached to multi-ingredient documents.
Thus this is a reproduced importer boundary defect, not a claim that this
particular condition remains in the repaired catalog.

**Correction and acceptance:** collect brand ownership and disqualifying evidence
across every label, including combination, unresolved and ambiguous labels,
before assigning any brand. A single-plus-combination collision must never
produce an unambiguous single-drug alias. Preserve the existing single-ingredient
and order-independence controls.

### F5 — P2: Fresh extraction accepts an endpoint its cache validator rejects

**Location:** `src/medkg/ingest/extract.py:46–48,55–70,86–88`.

Given the quote `Asterol is contraindicated for Orion syndrome.`, a scripted
extraction naming subject `Aster` passes the substring checks. If Aster is a
different known fictional drug, linking creates an edge for Aster. The very same
edge is rejected by `cached_edge_supported`, which requires an endpoint name or
alias with word boundaries in the quote.

Consequently, an incorrectly bounded model mention can enter the graph on its
first extraction even though a later cache pass rejects it. This tests handling
of malformed model output; no claim is made about its real-provider frequency.

**Correction and acceptance:** validate mention boundaries and linked endpoint
identity before accepting every fresh assertion, using the same policy as cache
reuse. Fresh and cached paths must agree on prefix collisions, aliases, punctuation
and empty quotes. A repair should preserve legitimate alias-based linkage rather
than merely require canonical names everywhere.

### F6 — P2: Rejecting a cached assertion does not remove its old graph edge

**Location:** `scripts/extract_openfda.py:40–45,86–87`;
`src/medkg/graph/store.py:92–98`.

The ordinary extraction script filters unsupported cached edges and rewrites
`extracted_edges.jsonl`, but only MERGEs retained edges into Neo4j. It does not
reconcile previously imported assertions or their conflict flags. When a prior
assertion becomes invalid, disk and summary can report zero while its old graph
edge remains queryable.

The actual `main()` entrypoint was run against an isolated fictional file tree
and a driver spy, retaining the real `GraphStore.load` implementation. One cached
assertion was rejected, the exported file contained zero assertions, and the
script issued **zero graph mutation calls**. Persistence of an already-imported
edge follows from the missing mutation; no real database was changed to prove it.

The preceding one-off migration explicitly reconciled its 18 quarantined edges.
This finding concerns subsequent ordinary extraction runs, not evidence that
those 18 relations are currently still present.

**Correction and acceptance:** reconcile the selected extraction scope and
recompute affected conflict flags. Preserve PrimeKG edges and assertions supported
by other chunks, including chunks outside the selected sample. A retain → reject →
rerun integration fixture must show consistent exported assertions, graph edges
and flags without deleting unrelated evidence.

### F7 — P2: Step references discard anchors without marking truncation

**Location:** `src/medkg/qa/pipeline.py:149–156`.

`$stepN` resolution sorts result IDs and silently takes the first 25. A valid
first query can return 26 rows under `LIMIT 100` without being truncated. In the
fictional two-step probe, the second count query receives only 25 anchor IDs;
the final result still has `truncated=false` and no partial-results notice.

This is separate from the corrected multi-anchor template union: the template
now handles every ID it receives, but the resolver already discarded another ID.
The scripted `Count: 25` illustrates how a partial aggregate can be presented;
the deterministically verified defect is the lost ID and absent truncation state.

**Correction and acceptance:** propagate truncation metadata through references,
or use bounded batches with correct distinct-target aggregation. Counts derived
from an incomplete anchor collection must not be presented as exact global
counts. Test 25, 26 and more than 25 duplicate rows, as well as genuinely truncated
upstream results.

### F8 — P2: Alternate minus signs are scored as positive counts

**Location:** `eval/score.py:41–46`.

Against expected count 2, both `Count: −2.` (U+2212 MINUS SIGN) and
`Count: - 2.` parse as positive 2 and pass. The numeric regex starts at the digit
and discards an unrecognized or separated sign. The existing `Count: -2.`
regression correctly fails, and ordinary `Count: 2.` correctly passes.

**Correction and acceptance:** normalize supported sign representations or reject
ambiguous signed spans before extracting the integer. These two negative forms
must fail while valid nonnegative integers and thousands grouping continue to
work. This is a scorer false-positive reproduction; historical score changes
were not estimated or recomputed in this review.
